# SukiUI.Motion.Playground

Визуальная отладка SukiUI.Motion. Зависит **только** от `SukiUI.Motion` (не от SukiUI) и
использует только публичный API — заодно проверяет, что библиотека живёт сама по себе.

Каждая сцена слева — один баг из ревью: что сделать, как выглядело до исправления, что
ожидается сейчас. Внизу — живая статистика тикера (`dispatch/s`): у простаивающего движка
должно быть **IDLE (0 кадров движка)**.

## Запуск

```bash
dotnet run --project SukiUI.Motion.Playground
```

## Сравнить «до» и «после» глазами

Playground собирается и со старым движком (до исправлений, коммит `c2bf6bcae`), поэтому
можно временно подменить исходники движка, посмотреть, и вернуть:

```bash
git restore --source=c2bf6bcae --worktree -- SukiUI.Motion
dotnet run --project SukiUI.Motion.Playground
git restore --worktree -- SukiUI.Motion
```

Последняя команда возвращает текущий движок из индекса (рабочее дерево снова чистое).
Тестовый проект в режиме «до» не собирается — это ожидаемо (в старом движке нет тестовой
точки подмены часов).

## Сцены

| Сцена | Баг | Что видно |
|---|---|---|
| Внешняя замена RenderTransform | 1 | сдвиг/поворот после замены `RenderTransform`; строка `Value` против реальной матрицы |
| Пружина во время пружины | 2 | быстрый hover in/out; график масштаба |
| Одиночная пружина телепортируется | 12 | пружина/Chain на свежем канале; график |
| Перезапуск идущей хореографии | 3 | счётчик завершений и `dispatch/s` в простое |
| Канал после остановленной хореографии | 9 | возврат через `Offer` после вытесненной хореографии |
| Тень из стиля общая для всех | 7 | три карточки с одной тенью из сеттера стиля |
| Жёсткие пружины и decay = 0 | 10 | график значения (NaN/1e128 печатаются числом), исключение валидации |
| SukiSpringEaseOut при ζ > 1 | 11 | кривые движка (сплошные) против точного решения (пунктир) |
| Записи движка перебивают стили | 6 (открыт) | текущее поведение; исправление — на этапе API |

Исследовательские сцены фазы 2 (Composition API, см. `SukiUI.Motion/ENGINEERING_NOTES.md` §7):

| Сцена | Что проверяет |
|---|---|
| C1 Анимация при занятом UI-потоке | SukiUI.Motion (UI-поток) замирает, composition (поток рендера) — нет |
| C2 Синхронизация Visual → CompositionVisual | перерисовка не ломает composition-Opacity, изменение `Visual.Opacity` — обрывает |
| C3 Нет чтения на UI-потоке | `comp.Scale`, прочитанный на UI-потоке, не меняется во время анимации |
| C4 Хит-тест и геометрия | hover следует нарисованной позиции; `TranslatePoint` видит позицию из layout |

`PlaygroundSmokeTests` в `SukiUI.Motion.Tests` строит каждую сцену и нажимает каждую кнопку
в headless — playground не должен ломаться незаметно.
